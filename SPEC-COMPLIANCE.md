## 🟙 Provided by the platform (GitHub Pages)

These are satisfied by hosting and need no code, but are **not configurable** from this repo:

- **HTTPS/TLS**, **HTTP/2**, **compression** (gzip/brotli), **Cache-Control**, **ETag /
  Last-Modified / 304**, **`X-Content-Type-Options: nosniff`**, and **HSTS** (the `github.io`
  apex is on the HSTS preload list).
- **XML sitemap** is generated by `@astrojs/sitemap` (`/sitemap-index.xml`).
- **Stable URLs / SSR**: the site is fully static-rendered, so all content and metadata ship in
  the initial HTML.

> If the site moves to a custom domain you control end-to-end (e.g. `pmcf.xyz`), revisit HSTS
> tuning (`max-age`/`includeSubDomains`/`preload`) and DNS **CAA** records.

## ⏳ Pending — needs root-domain or custom HTTP headers

GitHub Pages can't send custom response headers, and the site is served from the `/portfolio/`
**sub-path**. Both limits block the items below until the site moves to a root domain (e.g.
`pmcf.xyz`) and/or sits behind something that can set headers (Cloudflare, a reverse proxy, etc.).

- **Sub-path caveat for `robots.txt`, `/llms.txt`, `/.well-known/security.txt`:** these files are
  generated and committed, but crawlers/agents only read them from the **domain root**. Under
  `/portfolio/` they resolve to `/portfolio/robots.txt` etc. and are effectively ignored. They
  become authoritative automatically once the base path is `/`.
- **Clickjacking protection** (`Content-Security-Policy: frame-ancestors` / `X-Frame-Options`):
  header-only — `frame-ancestors` is ignored when delivered via `<meta>`.
- **HSTS**, **Permissions-Policy**, **Referrer-Policy (header form)**, **CSP via header** (the
  meta CSP is in place; a header version is strictly stronger): all header-only.
- **Cookie attributes**: no cookies are set today, so there's nothing to harden yet.

## ➖ Not applicable (no qualifying content today)

Re-evaluate if the site grows to include these:

- **Captions/transcripts** (no audio/video), **accessible data tables** (no tables),
  **feed discovery/hygiene** (no RSS/Atom feed), **breadcrumb UI** (single-level depth; JSON-LD
  breadcrumbs are present).
- **Privacy policy / cookie consent / GPC / analytics**: the site collects no personal data,
  sets no cookies, and runs no analytics. Add a privacy policy if/when any of that changes.
- **Internationalisation** (hreflang, RTL, language switcher, locale formatting, plural rules):
  the site is single-language (`en`). `<html lang>` and `og:locale` are set.
- **Form labels/errors, mobile input types**: the only form is the passphrase gate, which already
  has an associated `<label>` and an `role="alert"` error region.
